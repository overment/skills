# Methods

Open this before choosing how the base is organized, written and kept true. It lists names, not explanations, because you already know them. Recall the ones that fit, and add any others you know.

## Names, by problem

- **Organizing and finding:** PARA, Johnny.Decimal, Maps of Content, faceted classification (PMEST), controlled vocabularies, SKOS, information scent, card sorting, tree testing, llms.txt.
- **Units and links:** Zettelkasten, atomic notes, evergreen notes, backlinks, typed links, property graphs, normalization.
- **Writing:** BLUF, Every Page Is Page One, Diátaxis, DITA topic types, minimalism, plain language, progressive summarization.
- **Capturing:** GTD inbox processing, daily notes, commonplace book, CODE, incremental reading, the Feynman technique.
- **Keeping it true:** single source of truth, owners and review dates, ROT audits, KCS, ADRs, docs-as-code, handbook-first, search analytics.
- **Memory for agents:** episodic, semantic and procedural memory; consolidation; retrieval by recency, importance and relevance; core versus archival memory; facts with validity dates.
- **Volume:** sharding, entity resolution, idempotent intake, event sourcing, derived indexes (full text, embeddings, graphs).

## Choosing

- Don't let two methods decide the same thing: PARA and Johnny.Decimal both want the folders. Methods that decide different things combine freely.
- Tie each choice to a survey question, and drop any method that answers none.
- Name each change you make to a method, with its reason: "PARA areas, but no Resources folder: sources are linked from the notes that use them."

## Warning signs

- Every base you design comes out the same: always PARA, always Zettelkasten.
- A method adopted whole, including parts no question needs.
- Method names in the base's skill that the structure doesn't reflect.
