# Skills

Agent Skills by overment. They use the open [Agent Skills](https://agentskills.io) format, so they work in Claude Code, Codex, Cursor, and any other agent that reads `SKILL.md`.

## Skills

- **[skill-shaper](skills/skill-shaper/)** creates or reshapes a skill, checked against the skills you already have. It works out the job behind the request, decides whether a skill is the right tool, draws clear boundaries with neighbouring skills, and picks the lightest steering for the task: concepts and guiding questions for judgment work, exact steps for fragile work. It runs the task once without the skill first and writes only what that run gets wrong, and it keeps descriptions to one or two plain sentences.
- **[explainer](skills/explainer/)** turns a system, dataset or plan into one self-contained interactive HTML diagram: architecture and flows, sequence and state machines, 18 chart types (bar, line, scatter, waterfall, heatmap, treemap, Sankey and more), Gantt, timelines, kanban, journeys, story maps, database schemas, UML, and incident reports with an annotated timeline. Clicking any part opens a short explanation next to it in the graph: what it does, why it is there and what to watch, then its facts and relations, each said once. The text and panels that talk about it light up too. Every diagram has a bare view and a view with text, light and dark themes, and click-to-explore details. Its text follows plain technical English (about 80% of ASD-STE100), and `check` flags any sentence over 25 words. It lints before building, audits the result in Chrome and captures any state as PNG or SVG. Needs Bun.
- **[knowledge](skills/knowledge/)** designs and evolves knowledge bases that agents maintain: notes vaults, team handbooks, research archives, agent memory. Rather than handing over a fixed layout, it has the model recall established methods, derive the structure from the questions the base must answer, and prove the result with filing, finding, cold-start and load tests. Note types are small contracts, not forms to fill. The base gets an agent skill of its own, with where things go, how each source comes in, search recipes, upkeep routines and a copy of `check.ts` (links, required fields, drift; in full or for just the notes an intake touched), so later sessions keep it consistent without knowledge installed, up to hundreds of thousands of notes. Needs Bun.
- **[article-audio](skills/article-audio/)** turns a long Markdown article into one narrated MP3 with ElevenLabs Eleven v4. The agent rewrites the article for the ear: a listener on a walk without the article and a reader following along both get what they need. A figure is told by its point and the facts the text relies on, not by its shapes and colours, and code, tables and paths become plain speech. A script checks the text for what v4 misreads (square brackets become audio tags, slashes become IPA), splits it into fragments of about two minutes, generates them with request stitching so the voice stays even, and joins them with exact pauses and loudness normalisation. It uses the voice you name, or the default voice you set in `ELEVENLABS_VOICE_ID` or `~/.config/elevenlabs/voice_id`, with that voice's own stored settings, so a cloned voice keeps its owner's tuning. Every fragment and a manifest with chapter start times stay on disk, so a later audit can regenerate one fragment without touching the rest; a retake of unchanged text gets a new seed, because v4 repeats a take for the same seed. It spends API credits, so it runs only when invoked by name, asks before anything beyond a short sample, and reports what the API actually billed. Needs Node or Bun, ffmpeg and an ElevenLabs API key.
- **[free-memory](skills/free-memory/)** finds and frees what agent work leaves behind, in memory and on disk. For processes, it finds leaked test fixtures, orphaned dev servers and watchers, servers whose worktree was deleted, duplicates, forgotten log tails and abandoned test browsers. For disk, it finds finished git worktrees, build output such as Cargo target folders and node_modules, temp-folder leftovers and tool caches. A read-only scan collects the evidence (parent gone, folder deleted, open files, ports, CPU time, terminal, locks, unsaved edits, unmerged commits) and sorts every item into stop or delete, ask and keep, each with a reason. Ownership and use decide, not age, so large fresh build output in temp folders is found and live work is left alone. It leaves apps, agent sessions, main checkouts and anything a process or a lock holds. Its kill and delete commands act only on the last scan and check each item again: start times for processes; locks, edits, commits and changes for files. Worktrees go through `git worktree remove` without force, so branches stay. Works on macOS and Linux. Needs Node.js and git.
- **[transcribe](skills/transcribe/)** transcribes recordings with the [`transcribe`](https://github.com/overment/transcribe) CLI and Gemini. It covers only what an agent gets wrong without it: using the CLI instead of downloading a local Whisper model, speaker names in the wrong order, and lectures without section headings. Needs the CLI.
- **[unknown-unknowns](skills/unknown-unknowns/)** explores an unfamiliar topic with the user in short turns, to surface what they don't know they don't know. Each reply fits on one phone screen: one or two named "doors" tied to the user's goal, and one question the user answers in a word or a letter. The user steers the shape: "go on", "deeper", or "net", which casts 12–20 connected doors onto the map around the goal or any node and lets the user pick a branch. It asks for the goal first, finds where the user's knowledge stops with a list of terms instead of asking their level, often asks the user to guess before it explains, marks uncertain facts with "(check)", and ends with the open questions. It doesn't offer to build or write a report until the user asks. A live mind map in the browser shows the journey: a monochrome two-sided tree with a dot and a short name per node, filled by state (suggested, visited, current). It updates in place over Server-Sent Events, keeps the zoom and the open panel, and holds the detail the chat leaves out: a note per node, plus attachments such as HTML artifacts, images, PDFs, Markdown and links, which open in a full-screen lightbox. The keyboard walks the map (arrows, the journey in visit order, find); up to four marked nodes open side by side in a compare view; and a ? sheet lists the shortcuts and holds the settings for the highlight, the cross links, focus and the theme. The map runs from one Node script with no dependencies (Node 18+ or Bun).
- **[system-diff](skills/system-diff/)** turns a pull request or a commit range into one self-contained HTML report of what it changes in the system. It is for a reader who decides on the change and may not read code. The page has four layers, from the answer down to a changed line. First comes the decision, with numbered questions and a ★ on the recommended option. Then a map of the parts the change touches: solid for changed code, dashed for changed behaviour, faint for context. Then one section per part with before, after, why and the risk, and last every changed file with its hunks. Parts carry product names. The first sentence says what the system is, and the first use of a name links to a short chip in that same view. Before and after are what a person saw. At most one part starts open. Paths and hunks stay in one closed file index. The page is light, gray only, without kicker text, and works offline. A check script fails on any hue, any linked asset, any changed file the visible text does not name, and any changed path above that index. It does not judge whether a gloss is true. The report goes to `~/Downloads` under a stable name that a new run overwrites. A headless or off-screen check is part of building it. It is shown to the user only when they ask, and never from a sub-agent. Needs git and Node, and `gh` for GitHub pull requests.

## Install

Symlink a skill into your agent's skills folder, so `git pull` updates it everywhere:

```sh
git clone https://github.com/overment/skills.git
ln -s "$PWD/skills/skills/skill-shaper" ~/.agents/skills/   # Codex, Cursor
ln -s "$PWD/skills/skills/skill-shaper" ~/.claude/skills/   # Claude Code
```

Or install it in one project by linking into that repo's `.agents/skills/` or `.claude/skills/`.

Skills can steer an agent's tools and shell, so read one before you install it.

## Develop

Each skill has routing prompts and behaviour scenarios in `evals/`. Run them in a fresh session with and without the skill.
